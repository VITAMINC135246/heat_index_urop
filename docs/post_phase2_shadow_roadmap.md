# Shadow research after Phase 2

The work sequence is: accept the stabilized Phase 2 baseline; pause unrelated main-pipeline features; conduct Shadow research on a dedicated branch; validate a Shadow method independently; integrate it into the stable baseline; rerun the full scientific regression; then continue Heat Index research. This is a plan for later work, not a selection or implementation of a detection algorithm.

## Branch and change control

Keep `main` as the recorded scientific reference until the owner accepts the stabilization branch and chooses to promote it. Preserve the accepted commits and immutable run snapshots. After that decision, tag or record the exact stable development commit and create a branch such as `research/shadow` from it. Keep radiometric definitions, thermal artifact format, ambient interpretation, spatial acceptance rules, existing cover labels, and Part E baseline outputs frozen while comparing Shadow methods. Any necessary scientific-method change gets its own evidence and review. Integrate the Shadow branch only after its stated gates pass; do not rewrite baseline goldens to make the new feature appear equivalent.

## Questions to settle before coding

Review relevant literature and project-specific imagery to decide what “shadow” means in this research: visible cast shadow, partial shade, self-shadow, occlusion, or another physically defined condition. Decide whether the target is shadow at visible capture time, thermal capture time, or both, and whether their offset can change the label. Record expected spatial resolution, acceptable boundary uncertainty, ambiguous surfaces, saturation/glare, weather and sun-angle effects, and whether a human reviewer has enough evidence to label a pixel. Decide the unit of annotation (pixel, polygon, superpixel, or region), the independent ground truth process, and how uncertain cases will be excluded from a temperature comparison.

The present repository has separate cover and shadow layers and cover × shadow analysis hooks. It also has historical `shadow_status`/`shadow_flag` values and five all-zero tracked pilot thermal masks. Current mask generation can default an absent shadow column to zero, and the canonical writer treats any supplied binary mask as valid. Thus zero in an old mask does **not** by itself prove every pixel was reviewed as unshaded. Audit the annotation files, review decisions, mask generation version, and original imagery before assigning physical meaning to those zeros. Until that audit, classify their validity as unresolved for new scientific Shadow claims.

## Proposed data semantics

Keep physical surface and illumination independent: the same `surface_cover_class=concrete` can have either shaded or unshaded state. Represent physical state only where it is known, for example `shadow_state` in `{shaded, unshaded}` plus `shadow_valid` in `{true, false}`. `shadow_valid=false` covers missing, not processed, unreviewed, or ambiguous inputs; add a reason code when those cases must be distinguished. Preserve raw method output and reviewed final state separately. Attach method/version, capture time, source image, alignment/transform, reviewer, review status, and uncertainty to the mask's provenance. A stored zero must never silently stand for “not processed.”

The integration design should say how this model maps to the current `shadow_flag` (1/0/null) and `shadow_valid` fields without changing old accepted results. A transition or schema version may be required. Treat an old all-zero array as a legacy artifact with unresolved review state until evidence supports a more specific interpretation. Do not backfill validity from the array values alone.

## Dataset and annotation plan

Curate a small, access-controlled set of original visible/thermal pairs with a range of covers, genuine shaded and unshaded regions **within the same cover**, lighting conditions, times, and ambiguous boundaries. Include native dimensions, V/T pairing, accepted alignment/ROI, camera metadata, and thermal artifact provenance. Document sampling to avoid selecting only obvious dark areas. Use separate annotation and adjudication records, with at least a second review on disputed or borderline regions. Hold out images by capture/site or session to prevent near-duplicate leakage between development and evaluation. Keep a frozen positive example and a frozen no-shadow/missing-shadow example for regression.

Do not copy the entire raw project merely to test Shadow. Start with the smallest representative set permitted by research data policy. Preserve checksums and stable identifiers for the selected files; store large imagery locally or in controlled storage, while tracking compact schemas, manifests, and approved derived fixtures in Git if appropriate.

## Method evaluation and QA

Only after the definitions and annotations are settled, compare candidate approaches suggested by the literature and the dataset. Record each candidate's required inputs, calibration needs, expected failure modes, repeatability, computational cost, and explainability. Use the same frozen held-out images for all candidates. Tune thresholds or models on development data only; do not choose an approach from intuition or from agreement with an all-zero pilot mask.

QA must inspect native-grid registration, edge/boundary disagreement, missing data, inconsistent labels between visible and thermal coordinates, low-confidence regions, and reviewer overrides. Save overlays that show source imagery, cover, shadow state, validity, and ROI separately. A reviewer must be able to reject or mark uncertain areas rather than force binary truth. A geometry or provenance mismatch is a failure, even if a mask has plausible counts.

Report shadow-class precision, recall, F1 and intersection-over-union against reviewed labels, with confusion matrices and per-site/per-cover breakdowns. Also report valid coverage, invalid/ambiguous area, boundary sensitivity, cross-reviewer agreement, and failure cases. Avoid making aggregate accuracy the sole gate: a model that labels everything unshaded could score well on an imbalanced scene. Establish numerical acceptance thresholds from research aims and annotation reliability before final evaluation, and document confidence intervals or uncertainty where sample size permits.

## Integration and scientific analysis

The future method should produce a versioned, native-grid shadow state/validity artifact through the classification boundary. The canonical writer should combine that artifact with physical-cover labels while retaining both source records and the independent validity of each. It must not turn shadow into a new cover category, or infer shaded temperature from dark visible pixels without thermal alignment. Pixel-table evolution should add method/review provenance and, if needed, a validity reason while keeping existing `shadow_flag` consumers readable through an explicit versioned mapping.

Analysis should first report counts by `surface_cover_class × shadow_state × shadow_valid`, then compare ΔT between shaded and unshaded **within a physical cover** only when both groups satisfy predeclared sampling and image-coverage rules. Keep thermal source, temperature definition, ambient source, site/time and target eligibility as strata or modeled covariates. Distinguish descriptive differences from a causal “shade effect”; confounding by material, sun exposure, geometry, capture time and ambient assumptions remains. Figures should visibly indicate non-estimable contrasts rather than draw a line or bar for absent evidence.

Before merge, replay the old synthetic and accepted real scientific fixtures with Shadow disabled or unavailable and require unchanged established outputs. Add a reviewed positive Shadow fixture and test native-grid alignment, missing versus reviewed unshaded states, state/validity serialization, cover × shadow counts, exclusion of invalid pixels, and a non-estimable one-class case. Compare Windows-produced thermal artifacts on Mac for the same downstream result. A branch is mature enough to merge when the definition and annotation protocol are approved, held-out metrics meet the predeclared criteria, QA issues are resolved, old accepted results still pass, and the new cover × shadow findings have an explicit scientific review.
